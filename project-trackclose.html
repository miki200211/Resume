售後案件追蹤系統

售後維修案件追蹤系統：自動比對 JIRA 案件與客戶系統維修履歷，把每筆案件分流到正確分頁，一鍵回填與上傳。

PythonTkinterSelenium JIRA REST APITesseract OCR多執行緒

背景與問題

售後維修資料分散在 JIRA 與客戶維修履歷兩套系統。專員每天得人工比對成百上千筆資料、回填收/寄宅配單號、判斷哪些可以結案、哪些要跟催——既耗時又容易漏件、出錯。

解決方案

一套 Tkinter 桌面工具：自動爬取兩邊資料、把每筆案件智慧分類到四大分頁，專員一鍵即可回填或上傳 JIRA。系統分為三層：介面層、資料處理層、資料爬取層。

  • 介面層四大分頁：3 日返修 / 結案 / 跟催 / 原始資料；支援雙擊彈窗、複製、一鍵上傳 JIRA。
  • 資料處理層清洗與正規化原始資料、分類與分組案件，並自動產生回填用的標準化字串。
  • 爬取層JIRA REST API 抓取近一年案件；Selenium 登入客戶系統下載維修履歷（含 OCR 驗證碼辨識）。

技術亮點

  • 以關鍵欄位交集做智慧分類以（車牌、收到宅配單號、寄出宅配單號）為 Key，交集比對 JIRA 與維修履歷，自動分流到 3 日返修 / 結案 / 跟催。
  • Union-Find 群組綁定用併查集把 Labels 互相引用或客戶車號相同的多張 JIRA 單合併成一組，讓同群組一起結案 / 跟催，避免漏件。
  • 智慧文本萃取（預編譯 Regex）大量預編譯正規表達式，從雜亂的 JIRA 留言中精準抽取宅配單號、軟體版本、RMA 分析結果。
  • 非同步爬蟲 + 即時日誌爬蟲走背景執行緒，GUI 不卡死；QueueHandler 把背景執行緒的日誌即時送進 GUI 視窗。
  • 無頭模式 OCR 優化無頭模式下渲染比例太小導致驗證碼辨識失敗；強制 2 倍縮放 + Tesseract 字元白名單，大幅提升辨識率。

成果

把原本繁瑣的人工比對換成自動分類與一鍵操作，大幅縮短處理時間，並降低漏件與人為歸檔錯誤。
